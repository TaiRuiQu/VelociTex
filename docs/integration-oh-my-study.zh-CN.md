# oh-my-study 显示链路迁移

[English](integration-oh-my-study.md) | 中文

调研日期：2026-10-19，本次未修改下游源码。下文路径和行为都是调研时的快照；执行迁移前请重读真实源码和下游 AGENTS.md。

## 1. 现状与实际替换点

| 文件 / 类型 | 当前职责 | 迁移动作 |
| --- | --- | --- |
| `src/OhMyStudy.App/Services/NativeQuestionPresenter.cs` | 题目、选项、表格、图片、小题和反馈的原生容器 | 保留领域和 UI 组织，替换所依赖的 reading 服务 |
| `src/OhMyStudy.App/Services/NativeReadingSession.cs` | 收集正文、批量调用 Typst、整段 SVG 缓存、主题 / DPI 与复制 | 拆分正文宿主和单公式编译 / 绘制服务 |
| `src/OhMyStudy.Documents/TypstDocumentService.Reading.cs` | 将正文和行内公式一起排成 SVG | 在显示场景退出默认链路；打印调用继续保留 |
| `src/OhMyStudy.Documents/LatexFormulaConverter.cs` | 有界 LaTeX / mhchem → Typst | 显示数学交给 VelociTex；打印转换暂保留 |
| `src/OhMyStudy.Documents/DocumentText.cs` | 数学分隔符、规范化与正文扫描 | 优先复用，复核不能改写新库能识别的合法数学 |
| `src/OhMyStudy.App/Diagnostics`、`probes/OhMyStudy.Documents.Probe` | 实际宿主截图、阅读与文档回归 | 增加新链路用例，保留同条件旧链路基线 |

当前实现一次性编译整段文字和公式，SVG 中包含正文。因此把“单公式输出 SVG”的 API 塞进原调用点，并不能自动保留段落换行与行内基线。

最新调研记录在下游仓库的 `docs/verification/math-rendering.2026-10-19.md`。其中的 381.44ms 首次创建、约 0.83/0.88ms 缓存数据与 P95 9.54ms 切题，都是既有的小样本 CPU / 布局记录，不能直接充当本库与 KaTeX 的受控倍数基线。

## 2. 字体约定

下游旧约定要求界面使用无衬线字体。本轮用户明确允许 **数学公式使用 KaTeX 原版字体**；正文继续无衬线，打印沿用既有规则。迁移时把这个局部例外写入下游约定和设计记录，避免后续 Agent 为遵守旧规则再次把数学字体统一改成 sans。

用户没有授权用 KaTeX 字体改变普通界面字体，也没有要求本轮替换打印链路。

## 3. 目标调用流

```text
题目内容
  → 下游 DocumentText 扫描成 prose / inline math / display math
  → 数学片段：VelociTex 编译 → 不可变结果 / baseline / ink bounds
  → 下游段落宿主：正文排版、公式 inline object、换行 / 宽度
  → WinUI 原生绘制与交互
```

单公式 API 不接收外层 `$` 等正文分隔符。保留 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 的扫描、转义、显式换行以及未闭合时保留原文的行为。核心支持范围扩大后，正文 normalize 不能先用旧转换器过滤掉新库已支持的命令。

下游通过自己的 `IFormulaPresentationService` 或等价窄接口适配 VelociTex，不把 Question / Content 领域类型传进数学库，也不在库里复制题库模型。

## 4. 行内宿主与正文边界

P0 先验证原生 RichTextBlock + InlineUIContainer 的真实基线、行高与矩阵表现。通用 UIElement 的默认底边对齐并不等同数学基线，也不能仅靠看起来差不多的 Margin 修正当作通用方案。

如果 WinUI 宿主无法稳定表达所需基线，就采用 DirectWrite paragraph layout + inline object：由 inline metrics 返回公式宽、高与基线，draw 回调消费同一绘制结果。DirectWrite 的 [GetMetrics](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwriteinlineobject-getmetrics)为该模型提供基线相关度量。

这部分是下游适配的必要工作，不属于首版 Core 的正文引擎。选择 DirectWrite 自绘时，要同时处理整段 / 公式复制、键盘与基础语义，并评估普通正文已有的选择行为：需要保留的下游既有功能不能无记录地消失。跨正文与公式的连续选择、公式内部选择和编辑光标仍不在本库需求范围内。

如果只完成了独立公式、行内段落尚未达标，可以作为明确标记的过渡阶段并保留旧段落路径；只有混排同样完成后，才能宣称显示链路已全部替换。

## 5. 调度、缓存和呈现

- 完整公式到齐后在后台编译；复用 engine，限制并发上限，按字节预算保留结果，不为每个符号创建 XAML 元素。
- 由下游控制取消与请求代次，迟到结果不能覆盖新题；批次中的一个无效公式不影响其余正常公式。
- 字号、数学选项、宏上下文变化会让编译结果失效；主题默认前景只触发重绘，DPI 变化更新表面与映射而不重新解析。
- 宏默认按单条公式隔离；需要同文档共享时显式使用会话，禁止不同用户或消息随意共享全局定义。
- display 长公式维持字号并横向滚动；行内换行由宿主决定，不拆开分式或矩阵。表格沿用既有内容宽度约束排版。
- 正常显示中不要输出 PNG 或序列化 SVG 再交给 WinUI 解析，直接使用可绘制结果；导出 API 只在用户需要导出时使用。
- 出错或超限时保留完整可读、可复制的原文，并用简短的用户语言提示。诊断细节写日志，不把框架与阶段信息塞进界面。

## 6. 交互与无障碍

MathView 暴露单公式语义对象；复制菜单与键盘快捷操作可取到原始 LaTeX，宿主还可以另外提供整段复制。至少验证 AutomationPeer 的名称、角色、描述与焦点行为，并且不把原文和 MathML 重复朗读两遍。

下游可以给出“积分公式”这类简短描述；没有描述时公开源文作为基础回退。MathML 是独立输出，不假设 WinUI 会自动朗读任意 MathML。

## 7. 迁移与回退步骤

1. 固定旧链路样例与同条件基线，保留源码、构建与截图之间的关联。
2. 在本库打本地预发布包；下游通过集中版本与锁文件引用该包，不依赖开发机上的绝对目录。
3. 先接入独立公式与数学结果缓存，再接入已验证的段落宿主，覆盖全部调用点。
4. 用内部配置在新旧路径间切换，复核相同内容；不在正常产品页面展示引擎名。
5. 运行真实 Release AOT 应用的自动截图、功能与压力回归，检查默认页面与相邻区域。
6. 默认启用新显示路径；仅在过渡期内保留旧显示路径，且验证范围要明确。
7. 删除不再使用的显示转换、整段 SVG 解析与显示专属缓存；保留仍用于打印 / PDF 的 Typst 工具及转换逻辑。

不要在打包或显示迁移时顺手升级数据库、发布安装包或改写打印架构。

## 8. 下游完成检查

- 正文、选项、表格、小题、反馈、列表预览都跑过新路径。
- 一题少于 10 条、一页 50–100 条公式，首次显示、重复显示与快速切题，以及空内容、错误内容和超长内容全部通过。
- 至少复核既有 1440×960、720×960、460×960 场景，并补充 100/125/150/200% DPI 与深浅主题。
- 视觉上基线、标点、行距、分式与根号边界、滚动、表格宽度和相邻标题都没有回归。
- 复制、键盘、基础读屏与取消代次均有效；普通有效显示不会启动 Typst 子进程。
- 打印 / PDF 原有回归继续通过；未测试的物理打印、系统高对比度或真实多屏 DPI 明确列出。
- 所有 UI 改动都按下游要求自动截图并实际查看，不能用构建成功替代。

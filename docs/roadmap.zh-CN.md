# 分阶段实施路线

[English](roadmap.md) | 中文

本文把“尽早替换显示链路”和“最终达成完整核心兼容”拆成两次交付。P0、P1、P2 已于 2026-10-19 交付；常用子集、真实本地包消费、保留的栅格差异和未验证硬件见 [P2 记录](verification/p2-2026-10-19.md)。接续 P3 迁移和 P4 全部兼容，P5 尚未验收。阶段按依赖推进，不按未经验证的固定工期承诺推进。

## 阶段总览

| 阶段 | 目标 | 依赖 | 可交付结果 |
| --- | --- | --- | --- |
| P0 | 参考基线、原生 / AOT 可行性与验收工具 | 已确认需求 | 上游清单、可运行原生探针、对照管线、预算校准 |
| P1 | 紧凑核心骨架和最小垂直闭环 | P0 | 公式 → 数据布局 → 原生 / PNG / SVG / MathML |
| P2 | 常用数学预发布版 | P1 | 积分、矩阵等常见公式；可接入的本地 NuGet |
| P3 | 优先替换下游显示 | P2，段落宿主已验证 | oh-my-study 原生显示迁移和回退验收 |
| P4 | 补齐全部范围内核心 | P2；迁移反馈进入此阶段 | 全量核心兼容与差分报告 |
| P5 | 正式开源库交付准备 | P3 + P4 | 1.0 候选、本地包、消费验证、文档与许可证 |
| P6 | 持续性能优化 | 可复现正确性与性能基线 | 可审计的优化结果，逐步探索 ≥10× |
| P7 | 可选扩展层 | 需求另行确定 | 段落混排库化、其他平台或输出等 |

P3 可以先消费预发布版，不必等到 P4 才获得实际收益；P4 未完成时不得宣称“完整 KaTeX 兼容”。各阶段尽量串行闭环，避免提前铺开大量尚无验证入口的代码。

## P0：冻结基线、打通验证与原生探针

### 工作包

- **P0-01 上游获取。** 按 [锁定清单](reference/katex-0.19.0.lock.json) 校验 git 提交和 npm 归档，记录源文件、CSS、TTF、WOFF2 和字体映射的摘要，并锁定生成器的开发依赖与浏览器版本。
- **P0-02 兼容清单。** 用 AST / 注册表枚举命令、符号、内置宏、环境和选项，沿传递依赖补全。生成 `compatibility/core-0.19.0.json`，每项包含来源、是否纳入、排除理由、语义 / 视觉 / MathML 状态和 fixture ID；扩展与浏览器分类另做人工复核。
- **P0-03 字体核验。** 核对 20 个 TTF、OFL / RFN 声明、cmap 与 glyph id、TeX 度量和 TTF advance，量化 CSS 对符号大小和基线的真实影响，并制作单字形、斜体修正、数学轴和基线校准图。
- **P0-04 原生探针。** 最小 C# / AOT WinUI 程序加载私有字体，绘制显式 glyph run、根号路径和矩形横线，导出透明 PNG 与独立 SVG；验证 100/125/150/200% DPI、深浅主题、WARP、卸载 / 重载与设备资源重建。
- **P0-05 选型。** 验证轻量绑定与 Composition 表面；若关键回调、AOT 或 DPI 不成立，再比较 Win2D 表面。把实际选择、版本、发布参数和维护风险写入 ADR，选定后只保留一条首发实现路径。
- **P0-06 基线对照。** 用精确的 0.19.0 生成规范化语义结果、MathML、浏览器几何锚点与截图。浏览器在字体加载完成后采样，先跑 [公式种子集](examples/formulas.json)；同时将参考端与自身重复渲染对比，测出工具噪声。
- **P0-07 段落基线探针。** 用夹有公式的正文、分式、矩阵和标点验证 WinUI 宿主的基线、行高与换行。先确认 RichTextBlock 的 InlineUIContainer 是否够用；若基线无法精确表达，则采用 DirectWrite inline object 宿主方案，并写明其复制 / 无障碍行为以及对既有正文的影响。
- **P0-08 预算与硬件。** 固定开发机，确定旧 CPU 参考机或标注为未验证，测量原 Typst 链路与预热后的 KaTeX，校准内存与阶段预算，并记录 CPU / GPU / OS / DPI / 电源策略与软件版本。

### 出口

在全新进程中实际运行 AOT 探针，证明字体、原生绘制、两类图像导出和 UI 宿主路线可行；参考结果可重复生成；范围清单中没有未分类条目。P0 不要求完整的 TeX 解析器，也不允许用手工硬编码的公式探针冒充真实引擎。

若原生互操作出问题，在此阶段解决或更换选型，不把不可行的依赖带进 P2。若暂时没有旧硬件，该项保留为未验证并继续开发，但不得宣称已达旧 CPU 性能门槛。

## P1：基础架构与最小完整管线

### 工作包

- **P1-01 工程骨架。** 建立 slnx、统一 build props、集中包版本、锁文件、Nullable 与分析器，以及 Core / Windows / WinUI 项目、测试与样例。工具链对齐下游已验证的 .NET 10，不做未经验证的宿主 SDK 替换。
- **P1-02 数据与容器。** 生成静态字体 / 符号表，并实现 source slice、紧凑节点、payload、显式栈、workspace 与资源预算。
- **P1-03 词法和语法。** 基本符号、分组、上下标、基本宏展开、模式 / 样式切换，以及结构化源范围诊断与资源上限。
- **P1-04 布局。** 原子间距与 Bin 重分类、字体、上下标、简单分数、根号、自然宽度、基线与 ink bounds。
- **P1-05 同源输出。** 不可变 MathDocument，原生 glyph / rule / path 绘制，PNG / SVG / MathML；无效输入保留原文并返回诊断。
- **P1-06 生命周期。** workspace 隔离、结果不借用临时缓冲、线程与设备资源释放、取消与错误回滚。

### 出口

至少 50 个覆盖基本规则的有效 / 错误 fixture 通过语义、几何与输出检查；同一个公式在四种输出中语义与几何一致；真实 AOT 程序运行成功，导出结果被实际打开检查；热路径没有逐 token / 逐节点的 class 分配，分配与 native 资源都有基线报告。

本阶段就使用最终的数据架构，允许布局规则逐步增加，不允许先写一个临时 DOM 引擎再重写。

## P2：常用数学可接入预发布版

### 工作包

- **P2-01 常用数学。** 完成积分 / 求和 / 极限与 limits、广义分数 / 二项式、伸缩分隔符、重音、箭头、字体与数学文本。
- **P2-02 环境。** 矩阵族、array、cases、aligned 等常见环境，以及列间距与数组规则线。
- **P2-03 宏与选项。** 用户宏、局部作用域、常见定义与参数、行内 / 独立样式，并从完整清单中明确列出剩余事项。
- **P2-04 控件。** MathView、预编译结果绑定、主题 / DPI 失效、完整公式复制与基础 AutomationPeer；不引入公式编辑器。
- **P2-05 代表负载。** 1 / 10 / 50 / 100 条公式、缓存未命中 / 命中、复杂积分与矩阵，针对真实 AOT 消费程序测量。
- **P2-06 包与接口。** 打本地预发布 nupkg，提供不依赖 WinUI 的导出样例和 WinUI 显示样例，冻结第一轮公共接口。

### 出口

代表性普通负载的单条编译 P95 ≤10ms；至少 300 个经过冻结、按类别分布的 fixture 达到本阶段视觉门槛。三种导出可用，复制与读屏基础检查通过；未支持条目给出明确诊断，缓存与队列保持有界。

缺少旧机器实测时可以产出“待旧硬件验收”的预发布包，但不得宣称性能要求已全面通过。原生 prepare、submit 与实际呈现耗时必须单独报告，不能把布局偷偷挪到核心计时之外。

## P3：迁移 oh-my-study 的显示链路

按 [迁移方案](integration-oh-my-study.zh-CN.md) 执行：先把公式字体例外写进下游约定，再接入本地包或固定版本的预发布包。

### 工作包

- **P3-01 调用边界。** 保留现有数学分隔符扫描和领域对象，把单条公式交给 VelociTex，并替换显示阶段的 LatexFormulaConverter / Typst 依赖。
- **P3-02 宿主段落。** 使用 P0 选定的路线处理正文、行内公式、基线、换行和 display 块；这一层属于下游宿主，不塞进 Core。
- **P3-03 场景完整性。** 正文、选项、表格、小题、反馈和列表预览一致接入；保留错误原文、取消与代次保护、长公式滚动。
- **P3-04 视觉与流程。** 自动运行真实 AOT 应用并截图，覆盖主题、DPI、宽窄窗口与缓存状态，同时检查相邻区域；保留打印 / PDF 原链路的回归。
- **P3-05 测量与切换。** 用同样例、同缓存状态、同构建测量前后延迟与内存。默认切换到新显示链路，保留有期限的内部回退开关，确认稳定后移除显示专属旧代码。

### 出口

下游默认显示路径已使用新库，目标场景有运行与截图证据，普通有效数学显示不再调用 Typst。打印仍可依赖 Typst，不能因此错误地删除整条工具链。

若只是替换了独立公式、混排段落仍走 Typst，则记录为“部分迁移”并继续完成 P3，不宣布为完整显示替换。

## P4：全量核心兼容

### 工作包

- 按清单补齐剩余的核心命令、宏行为、Unicode 映射、特殊盒、尺寸单位、标签与编号以及少见环境。
- 完成持续宏会话、错误范围与诊断策略，并验证嵌套、作用域恢复与失败回滚的差异。
- 规范化 MathML 对照覆盖所有范围内节点，补齐导出颜色、路径变换和特殊几何。
- 从上游测试、支持文档和生成用例扩充语料，建议不少于 1,000 个独立有效数学 fixture，并包含负例与极端合法输入。
- 范围内每条注册项都有语义和至少一个排版 / 输出用例；符号按字体和原子类别生成覆盖，不靠重复同一公式截图凑数。

### 出口

范围内功能覆盖 100%，所有数学内容正确性硬检查通过；视觉检查达到 [验证门槛](validation.zh-CN.md)，不存在未解决的缺字、错序、裁切、基线或结构问题。所有例外都有可审计理由，不能靠把未实现条目移出范围来清掉失败。

## P5：1.0 候选与发布准备

- 公共 API 稳定，XML 文档、错误码、资源上限与线程 / 生命周期契约齐全。
- 本库 MIT 许可证、KaTeX MIT、字体 OFL / RFN、来源清单和依赖说明随包携带，包内不含开发用浏览器或 Node 依赖。
- SourceLink、符号包、确定性构建、包验证、兼容性说明、安全输入边界与变更日志齐备。
- 在干净消费工程中从本地 feed 还原，构建 JIT 与 Native AOT 并实际运行，覆盖原生显示、PNG、SVG、MathML、字体加载与基础无障碍。
- 下游默认链路验收、旧 CPU 性能证据，以及内存压力 / 取消 / 设备失效 / DPI 切换证据齐全，未覆盖的平台说明需保留。
- 冻结 1.0 候选 nupkg、报告与复现命令；确认包名与仓库身份后，再按用户授权对外发布。

## P6：持续优化与 ≥10× 探索

优先采用不改变排版的优化：

1. 解析 / 宏热点的连续数据、减少字符串和重复遍历。
2. workspace 的预热复用、确定大小的输出写入、减少复制与大对象保留。
3. 字形与文本 shaping 的有界复用；复用时正确处理宏副作用。
4. 相邻 glyph run 合并、路径复用、减少 native 调用和表面更新区域。
5. 批量布局、下游可见内容调度与缓存；防止队列和并发内存上升。
6. 仅在可证明受益时引入 SIMD / SoA 专用布局；提供旧 CPU 的标量回退。

每项优化都要在相同语料上给出前后的语义 / 几何、延迟分布、托管 / native 分配和内存报告。只有在等价工作量、相同缓存与预热条件下才能宣称加速倍数，不把浏览器启动或帧同步等待计入算法收益。完整目标定义见验证文档。

## P7：后续可选层

可以把下游验证过的段落宿主提炼为可选的混排模块；其他平台、ARM64、打印 / PDF、扩展命令和编辑交互都需要新的需求确认，不默认进入首版。

[English](requirements.md) | 中文

## 1. 产品目标（用户已确认）

在 C# 中构建独立的数学排版与渲染库，供 WinUI 3 原生界面快速显示完整公式。首个下游是 `../oh-my-study/`，优先替换该项目的现有公式显示链路。产品以独立开源 NuGet 库交付，代码采用 MIT 许可证。

排版参照唯一锁定 **KaTeX 0.19.0**。目标尽可能做到 1:1，一般公式至少还原约 95% 的视觉意图；验收关注数学排版一致性，可接受抗锯齿以及细微的字体与间距差异。“95%”不表示可以随意漏掉 5% 的命令，也不是简单的像素相同率。可执行的几何与视觉门槛见 [验证与性能](validation.zh-CN.md)。

性能分两层：首版先还原效果，同时保持足够快的速度；后续版本再追求比浏览器 KaTeX 快一个数量级。首版不以 ≥10× 为发布条件。

## 2. 平台与运行时（用户已确认）

| 项目 | 确认边界 |
| --- | --- |
| 语言 / 平台 | C#、.NET 10 |
| 首发系统 | Windows 10/11 x64；工程最低系统基线采用下游已有的 Windows 10 19041 |
| 发布 | Native AOT 可用；同时保留便于调试的 JIT 构建 |
| 原生显示 | WinUI 3；禁止借助 WebView 或浏览器完成运行时公式呈现 |
| 图形依赖 | 允许系统 DirectWrite / Direct2D 与轻量 C# 绑定；具体绑定和显示表面在 P0 实测后锁定 |
| 核心边界 | 数学核心不依赖 WinUI；平台无关的结构为后续复用留接口，不承诺首发跨平台 |
| CPU | 覆盖约十年前的常见 x64 CPU，不以 AVX2、AVX-512 或现代独显作为前提 |
| ARM64 / 其他 .NET | 首发不要求 |

WinUI 宿主、Windows App SDK 与 SDK 工具链的版本，必须在 P0 与下游锁文件一起验证；仅凭包宣称支持某系统，不算实机验收。

## 3. 数学兼容范围（用户已确认）

纳入该固定版本的核心数学命令、符号、样式和数学环境，以及用户宏与分组作用域。行内与独立两种公式样式都包含在内；核心环境内部的分行、矩阵、对齐和公式标签属于数学布局。

当前范围之外：

- HTML、DOM、CSS 注入以及浏览器专属行为。
- 链接、外部图片和其他资源访问命令，如 `\href`、`\url`、`\includegraphics`。
- `mhchem`、自动扫描网页、copy-tex 等 contrib 扩展。
- 任意 LaTeX 包、完整 TeX 文档编译与 JS 回调形式的扩展宏。
- 对其他 KaTeX 版本的兼容承诺。

**源码中的注册位置不决定范围归属。** P0 从注册表、符号表、内置宏和数学环境中提取完整清单，再逐项标注。作为核心数学实现依赖的内部辅助命令，即使名字里带 HTML，也必须保留所需语义，不能按文件名一刀切删除。`CD` 这类位于核心源码中的数学环境，也不能因为少见就归为扩展。清单依据 [0.19.0 函数入口](https://github.com/KaTeX/KaTeX/blob/v0.19.0/src/functions.ts)、[环境入口](https://github.com/KaTeX/KaTeX/blob/v0.19.0/src/environments.ts) 及其传递注册依赖。

首个可接入的预发布版可以只覆盖常用子集，并公布剩余清单；只有当范围内条目全部实现并验证后，才能正式宣称“完整核心兼容”。超出资源限制的输入另有明确诊断，不计为普通兼容用例。

## 4. 字体、呈现和输出（用户已确认）

- 数学公式允许使用原版 KaTeX 字体；公式周围的正文继续使用无衬线字体。
- 原生显示直接绘制排版结果；另外必须输出 **PNG、SVG、MathML**。
- 支持复制完整公式源码和基础无障碍；不要求公式局部选择、跨正文与公式的连续选择、公式内编辑光标或链接交互。
- 不要求流式输入；收到完整公式后再渲染。
- 首版核心 API：“校验公式 → 返回可绘制结果、尺寸、基线和诊断”。
- 正文与公式混排、段落换行属于后续可选能力，通常由下游承担。
- 首次迁移保留现有打印链路；本轮不承担 PDF 或打印引擎的替换。

复制与基础无障碍的工程定义：原文可完整复制，并可用键盘触发复制；公式作为单个语义对象暴露名称、源文本和必要描述，便于下游提供自然语言说明。MathML 导出并不自动等于 Windows 读屏支持，也不承诺完整的数学结构语音导航。

## 5. 负载与响应（用户已确认）

| 维度 | 需求 |
| --- | --- |
| 一题 | 通常少于 10 条公式 |
| 一页 | 约 50–100 条公式 |
| 更新 | 完整公式到齐后处理，无逐 token 增量渲染 |
| 延迟 | 字体与设备初始化完成、且无公式缓存时，单条公式从校验到布局并生成可绘制结果 **P95 ≤10ms** |
| 其他耗时 | PNG / SVG / MathML 导出、首次进程启动、整页呈现分别测量和设预算 |
| 内存 | 尽量小；缓存与工作缓冲区有界，不用高内存换取表面上的速度 |
| 语料 | 可以生成微积分、矩阵等复杂代表公式，不依赖真实用户资料 |

10ms 适用于冻结后的代表性普通负载，不要求任意长度的极端公式都在 10ms 内完成。有效范围、异常负载和导出尺寸限制必须公开。具体硬件尚未指定：P0 建立约 2015–2017 年低功耗双核 / 四线程 x64 基线；没有该类设备的实测证据时，不能把现代开发机的结果当作旧 CPU 验收。

## 6. 架构原则（用户已确认）

可以接受上游算法移植、构建期数据提取和差分验证，但底层架构要重新设计，而不是逐行翻译上游实现。紧凑数组、arena、源切片、池化以及后续的 SIMD 等手段都可以积极采用。

工程执行原则：语义与排版规则保持忠实，存储与调度重新设计。先把正确性和原生闭环做出来，再依据测量持续优化；不能先堆起大量难以优化的临时对象树，再把数据导向的改造全部推到末期。

## 7. 决策状态

用户需求已确认，本文中已确定的事项无需重复提问。以下是实现期间的技术决策，由 Agent 在授权范围内凭证据完成：

- 绑定库和 WinUI 绘制表面的实际选型。
- 经 P0 校准的视觉阈值、阶段性内存和导出预算。
- 下游原生段落适配的具体实现。
- 正式 NuGet 包名可用性、仓库地址、发布身份与签名配置。

最后一项不影响本地开发、打包与验收；对外建仓、上传或发布需用户另行授权。

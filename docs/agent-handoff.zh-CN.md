## 1. 已确定，不应反复询问的事项

- C# / .NET 10、WinUI 3、Windows 10/11 x64、Native AOT；允许用轻量绑定调用 DirectWrite / Direct2D。
- 唯一兼容目标是 KaTeX 0.19.0 核心数学，包含用户宏与作用域，排除浏览器功能与 contrib 扩展。
- 允许使用 KaTeX 原版数学字体，正文仍为无衬线；接受抗锯齿和细微排版差异。
- 基础架构重新设计，保留上游数学规则，采用紧凑数据结构与可复用的工作区。
- 需要原生显示、PNG、SVG、MathML，以及完整公式复制与基础无障碍；不需要编辑器和流式更新。
- 首版核心以单条完整公式为单位；正文混排与自动换行主要留在下游，后续可提炼为可选层。
- 初始化完成且没有公式结果缓存时，单条公式从校验到完整绘制结果的 P95 ≤10ms；≥10× 是后续优化目标。
- 典型一题少于 10 条公式、一页 50–100 条；目标机器是约十年前的 x64 CPU，内存占用要低。
- MIT 开源 NuGet，优先替换 oh-my-study 的显示链路，现有打印链路暂时保留。

原始确认与范围详见 [需求与边界](requirements.zh-CN.md)。工程预算、具体依赖和视觉阈值按 P0 证据校准，不要说成用户指定数值。

## 5. 技术风险与解法

| 风险 | 应对与完成证据 |
| --- | --- |
| TTF、KaTeX 度量与浏览器实际 advance 不完全一致 | 在 P0 做单字形 / 样式校准；以来源规则加实测确定几何，不随手改度量 |
| WinUI / 绑定版本在 AOT 下出现资源或回调问题 | 先发布并运行最小真实消费程序；选定依赖后锁定版本 |
| 独立公式正常，混排替换却退化 | P0 先证明基线宿主；P3 必须覆盖正文、标点和表格 |
| 宏副作用与缓存冲突 | 默认隔离；会话显式、成功才提交；含写操作的请求先禁用结果缓存 |
| SVG 与原生字体 / 路径不一致 | 从同一绘制结果导出，路径字体与摘要锁定，并独立打开检查 |
| 自绘导致读屏或复制不可用 | MathView 提供基础 AutomationPeer 加键盘 / 原文复制；MathML 不充当 UIA 实现 |
| 没有旧 CPU 实测机器 | 继续实现但保留未验证状态，不用现代机的预测当作达标 |
| 极端公式污染池或撑爆图像 | 有界栈 / 节点 / 缓存 / 导出像素，超大缓冲不常驻，并测试出错后的恢复 |
| 对照覆盖只剩简单公式 | 保留完整功能分母，按类别统计，并覆盖特殊盒、CD、标签、宏与错误 |
| 后期为追求倍数而牺牲精度 | 每次优化同步跑差分、内存与 AOT 检查，只宣称等价工作量下的实测结果 |

## 6. 阶段交付说明格式

每次交付更新一份简短维护记录，至少包括：

- 完成的阶段 / 工作包、实际行为和涉及的接口。
- 本轮源版本、依赖 / 字体 / 生成数据摘要与可复制命令。
- 通过、失败、未执行项；截图 / 差分 / 计时原始数据的位置。
- 兼容清单的变化、已知差异和剩余工作。
- 下一步最小闭环。

没有真实截图时不说 UI 验收通过；没有旧 CPU、真实 AOT 消费程序或已发布包测试时，逐项写明。历史证据可以复用，但被本次改动影响的部分必须更新。

# Combined NuGet/npm release CI verification — 2026-10-19

The user requested npm CI publication and clarified that it should accompany the
existing release tag. The implementation therefore extends `publish.yml` and
keeps the existing **`v*` trigger**. No separate npm tag or workflow dispatch is
needed for releases.

## Final behavior

- The tag version is shared by NuGet and npm. A prerelease goes to npm `next`;
  a stable version goes to `latest`.
- `wasm.yml` is reusable for release builds and remains a non-publishing
  branch/PR/manual verification workflow. Both native and web verification must
  succeed before either registry job can run.
- `build-wasm.ps1 -PackageVersion <version>` stages the npm package and lock in
  `artifacts/wasm/npm-package`. Tracked npm metadata is untouched. The build
  records the source revision, actual working-tree state, version and version
  origin. Release publication requires a clean tagged source build.
- A dedicated publish job uses GitHub environment `npm`, OIDC and pinned npm
  11.16.0 on Node 22.23.2. It downloads the tested tarball from this same run,
  verifies the hash, source, version, AOT status and registry identity, then
  publishes those exact bytes with provenance and lifecycle scripts disabled.
  It does not check out source or rebuild the package. No npm token is stored.
- GitHub Release creation waits for both NuGet and npm publication. Registry
  writes are not a distributed transaction; partial success requires retrying
  only failed jobs. Duplicate versions deliberately fail.

## External setup / unverified

The `npm` GitHub environment and npm Trusted Publisher must be configured by an
authorized package maintainer, with workflow filename **`publish.yml`**,
environment **`npm`** and explicit permission for direct **`npm publish`**. A
package that does not exist yet needs its initial publication before configuring
its package settings. See [setup instructions](../npm-publishing.zh-CN.md).

GitHub-hosted/Linux execution, npm OIDC exchange, provenance generation, public
registry upload and actual simultaneous release remain **unverified**. No tag,
commit, push, package publication, remote environment or trust-policy mutation
was performed. Native code, native package payloads and WinUI UI are unchanged;
this CI change does not revalidate or clear outstanding P5 hardware/audio gates.

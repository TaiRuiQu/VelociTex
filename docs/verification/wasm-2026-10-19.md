# WASM / JS npm preview verification — 2026-10-19

This implements the user's subsequent request for an optional browser binding.
It does not replace or modify the frozen native `1.0.0-rc.1` package bytes, clear
native P5 hardware gates, or claim a speedup over KaTeX.

## Delivered

- `VelociTex.Rendering.Svg`: portable SVG export from the existing immutable
  drawing commands, preserving order, colors, affine transforms, clipping, ink
  overhang and invisible formulas. No DirectWrite, browser font measurement or
  DOM layout is used for math layout.
- All 20 checksum-locked KaTeX 0.19.0 fonts supply 2,255 glyph contours, extracted
  at build time with pinned FontTools 4.60.1. The deterministic committed outline
  resource is 1,259,232 bytes. Original font bytes remain unchanged. Their OFL/RFN
  license is retained separately from MIT code.
- `VelociTex.Wasm`: .NET 10 `browser-wasm`, Release AOT by default, single-threaded,
  with explicit JSON/JSExport boundaries and the existing bounded Core workspace.
- `npm/velocitex`: ESM package, TypeScript declarations, automatic shared runtime
  initialization, `render`, `renderToString`, `renderAll`, `ParseError`, static
  asset copy CLI, distribution guards and all font/.NET runtime notices.
- Standalone browser sample, bundled-app instructions, separate web solution,
  reproducible `build-wasm.ps1` / `verify-wasm.ps1`, and a WASM/npm CI workflow.

Native Core sources, Direct2D and WinUI implementation are unchanged. The web
adapter is a separately authorized platform extension; native packages acquire
no browser, Node.js or JavaScript runtime dependency.

3. Release WASM AOT publish succeeded. `npm pack` checks the AOT build metadata,
   runtime entry point, declaration files and separate font/runtime licenses.

## Size and timing observations

The local `velocitex-0.1.0-preview.1.tgz` contains 84 files, approximately **12 MB**
compressed and **24.6 MB** unpacked. It includes raw, Brotli and gzip variants.
The final local tarball SHA-256 is
`24069555443d22a287dd476200e54b5f45590d2b4febf377394be784c0cd69a4`.
The actual first browser session requests 24 runtime resources totaling
**16,851,437 bytes uncompressed**. Summing their provided compressed siblings
gives **3,102,054 Brotli bytes** or **4,494,781 gzip bytes**. Those compressed sums
are file sizes, not measured production HTTP transfer: the verification server
serves uncompressed content. Hosts must configure content negotiation to use
the precompressed assets, or apply their own HTTP compression.

One isolated localhost run took about 334 ms to initialize and finish the small
mixed startup scenario; 100 subsequent fraction/radical HTML exports took about
73 ms total. These are smoke observations on this development machine, without
network throttling or an equivalent KaTeX comparison. They establish neither a
P95 performance guarantee nor browser superiority. Browser heap, GC, native
resources and low-memory/mobile peaks were not measured. The generated WASM
linker configuration starts with a 32 MiB linear-memory allocation; that is not
the total browser memory footprint.

## Remaining work / unverified

- **29 P4 otherwise-valid inputs require missing fonts or platform shaping** and
  explicitly report `UnknownSymbol` in this browser preview. The other 50 cases
  are the existing invalid-input fixtures. Chinese math text and contextual
  script fallback need a portable shaping/font implementation; ordinary Chinese
  body text belongs to the web host and is unaffected.
- Safari, Firefox, mobile browsers, assistive-technology audio, production
  bundler/CDN deployments, production compression and real network startup are
  **unverified**. Static relocation is browser-tested, but no Vite/webpack build
  is claimed. The DOM scanner works within one text node and must be called
  again for newly inserted content; no mutation observer is installed.
- The new hosted CI workflow and its Linux execution are **unverified** locally;
  source syntax checks ran, but GitHub Actions/actionlint execution did not.
- Full Windows P4 Native AOT regression was not rerun in this change; the new
  portable renderer's own actual Native AOT oracle was run. No WinUI interface
  changed, so no new WinUI visual acceptance is claimed or required.
- npm registry lookup for `velocitex` returned 404 on 2026-10-19. This neither
  reserves the name nor proves publication authorization. **No npm/NuGet publish,
  remote push, upload or release was performed.**
- Node.js SSR, contrib extensions, implicit cross-formula macro sessions, full
  text selection and automatic formula line breaking are not implemented.

## Reproduce

```powershell
# Pinned SDK must already be installed.
dotnet workload install wasm-tools --skip-manifest-update
npm ci --prefix tools/reference
./build-wasm.ps1 -Locked
./verify-wasm.ps1 -SkipBuild

# Optional portable Native AOT oracle comparison on Windows:
dotnet publish tests/VelociTex.Web.Tests -c Release -r win-x64 -p:PublishAot=true -p:RestoreLockedMode=true -o artifacts/wasm/native-aot
./artifacts/wasm/native-aot/VelociTex.Web.Tests.exe artifacts/wasm/parity-aot.json
Get-FileHash artifacts/wasm/parity.json,artifacts/wasm/parity-aot.json
```

Font regeneration needs Python with
`tools/VelociTex.DataGeneration/requirements-wasm.txt`; ordinary builds consume
the committed resource. The Windows browser test uses installed Chrome unless
`VELOCITEX_BROWSER` overrides it; other platforms use pinned Playwright Chromium.

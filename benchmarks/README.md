# Benchmarks

Three presentation paths are measured on one frozen workload:

| Harness                                | Path                                       | Timed region                                                                |
| -------------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------- |
| `VelociTex.Benchmarks`                 | Windows native C++ Core + Direct2D exports | LaTeX → MathML, SVG, and compile-only                                       |
| `VelociTex.WinUI.Bench`                | Windows native WinUI `MathView`            | `TryCompile` + `Result` assignment through the second composition frame     |
| `browser/bench.mjs --engine velocitex` | npm WASM binding                           | `renderToString` MathML/SVG and `render` through the second animation frame |
| `browser/bench.mjs --engine katex`     | KaTeX 0.19.0 in Chrome                     | `renderToString` MathML and `render` through the second animation frame     |

The same [workloads.json](workloads.json) drives all four harnesses. It contains
six single formulas, three long single-formula blocks, and three mixed
text/formula pages (8–10 formulas each). The benchmark refuses to skip an input:
every formula must compile and produce non-empty output before timing starts.

## Results

The 2026-10-20 run is recorded in [results/2026-10-20](results/2026-10-20) and
summarized in [docs/benchmarks.md](../docs/benchmarks.md). The charts are
generated by `plot_benchmarks.py`; the rendering comparison poster is composed by
`compose_comparison.py`.

Key P50 values (milliseconds per formula; page values divided by the average 9
formulas):

| Workload | Native MathML | WASM MathML | KaTeX MathML | Native SVG | WASM SVG |
| -------- | ------------: | ----------: | -----------: | ---------: | -------: |
| Single   |         0.096 |       0.195 |        0.085 |      0.465 |    0.370 |
| Long     |         0.646 |       0.425 |        0.520 |      2.046 |    0.900 |
| Page     |         0.067 |       0.096 |        0.043 |      0.364 |    0.171 |

Call-to-presented-frame P50: native 64.6 ms, WASM 32.3 ms, KaTeX 32.0 ms for a
single formula. The native window was composited at 31.5 ms per frame (about
30 Hz) while headless Chrome used 16.7 ms (60 Hz), so compare the frame-independent
sync figures as well. Page throughput was 139 / 280 / 280 formulas per second
(native / WASM / KaTeX).

## Prerequisites

- Windows x64, .NET SDK 10.0.402, Visual Studio C++ x64 build tools.
- Node.js 22 (the repository's pilot environment is at
  `artifacts/tooling/node-v22.14.0-win-x64`).
- The locked KaTeX 0.19.0 package at `artifacts/tooling/katex/package` (the npm
  tarball is `artifacts/tooling/katex-0.19.0.tgz`).
- Chrome at the default installation path. Pass `--chrome <path>` to override.
- Python 3 with matplotlib for the charts.

## Native parse/export

```powershell
./native/build-core.ps1
dotnet run --project benchmarks/VelociTex.Benchmarks -c Release -p:Platform=x64 -- `
  --iterations 300 --out artifacts/benchmarks/native
```

Set `VELOCITEX_NATIVE_DIR` to `artifacts/core-native` if the native Core DLL is
not resolved automatically. `--render-comparison <dir>` writes the transparent
2× PNGs used by the comparison poster.

## Native WinUI end-to-end

```powershell
dotnet build benchmarks/VelociTex.WinUI.Bench -c Release -p:Platform=x64
./benchmarks/VelociTex.WinUI.Bench/bin/x64/Release/net10.0-windows10.0.26100.0/win-x64/VelociTex.WinUI.Bench.exe `
  --out artifacts/benchmarks/winui
```

The app opens one real window, warms DirectWrite/Direct2D/WARP and composition,
then records `TryCompile`, the synchronous `MathView.Result` assignment, and the
next two composition frames. It writes `winui-report.json` and a BMP screenshot
of the last page so the run can be visually verified.

## Browser

Build the npm distribution first:

```powershell
./build-wasm.ps1
node benchmarks/browser/bench.mjs --engine velocitex --out artifacts/benchmarks/wasm `
  --iterations 60 --e2e-iterations 10 --page-rounds 6
node benchmarks/browser/bench.mjs --engine katex --out artifacts/benchmarks/katex `
  --iterations 60 --e2e-iterations 10 --page-rounds 6
node benchmarks/browser/capture-comparison.mjs --out artifacts/comparison
```

The harness starts a local HTTP server (COOP/COEP enabled), launches headless
Chrome with a fresh profile, drives it through the DevTools protocol, and saves a
report plus a page screenshot. `--headful` is available for inspection. Timed DOM
renders force layout before reading `performance.now()`, then wait for two
animation frames so the frame containing the change has been presented.

## Charts and comparison poster

```powershell
python benchmarks/plot_benchmarks.py --data artifacts/benchmarks --out docs/benchmarks
python benchmarks/compose_comparison.py --data artifacts/comparison --out docs/benchmarks/comparison-overview.png
```

Charts use a white background, a single accent palette, value labels, and explicit
footnotes. The comparison poster puts the actual native PNG, WASM screenshot, and
KaTeX screenshot in bordered white cards at equal 32 px math em size.

## Interpretation

- Timing is per machine and per build. Do not present these numbers as universal.
- Frame-pacing dominates call-to-presented-frame results. Report the sync numbers
  alongside them whenever the compositor cadence differs.
- KaTeX 0.19.0 has no native SVG output; the SVG comparison is native vs WASM.
- The C++ MathML fast path rejects environments it cannot render exactly, such as
  `cases`, so those formulas use the exact C# fallback. This is counted honestly.
- The native page uses `TextBlock` and inline `MathView` rows; Core does not own
  body-text paragraph wrapping.
